1. RESUMEN EJECUTIVO
====================

GTAAPP es una aplicación web de mapeo interactivo y gestión de datos para los videojuegos Grand Theft Auto V y Grand Theft Auto VI. Está construida con una arquitectura SPA (Single Page Application) moderna que combina ASP.NET Core 10.0 como backend y Angular 20 como frontend.

La aplicación permite a los usuarios:
- Visualizar mapas interactivos de GTA V con múltiples capas (satélite, carreteras, atlas, UV, etc.)
- Gestionar propiedades, negocios, vehículos y coleccionables del juego
- Sincronizar datos con Rockstar Games Social Club
- Crear marcadores personalizados en el mapa
- Ver información detallada de ubicaciones y POIs del juego

2. ARQUITECTURA GENERAL

- Separación de responsabilidades: Backend/Frontend claramente separados

2.2 TECNOLOGÍAS PRINCIPALES
---------------------------
BACKEND:
- Framework: ASP.NET Core 10.0 (.NET 10.0)

- API: REST con Controllers

- Lenguaje: TypeScript 5.8.3
- Build: Angular CLI 20.3.37
- Mapas: Leaflet 1.9.4
- Icons: FontAwesome 7.3.1
- HTTP Client: HttpClient de Angular

INFRAESTRUCTURA:
- Almacenamiento: Archivos JSON locales
- Sistema de archivos: wwwroot/ para estáticos
- Configuración: appsettings.json

3. CONFIGURACIÓN Y DESPLIEGUE
==============================

--------------------------
- .NET 10.0 SDK o Runtime
- Node.js 18+ (para desarrollo del frontend)
- npm 9+ (para gestión de dependencias)
- Sistema operativo: Windows, Linux, macOS

3.2 CONFIGURACIÓN DEL BACKEND
-----------------------------
Archivo: GTAAPP.Server/Program.cs

CONFIGURACIÓN DE SERVIDOR:
- Kestrel configurado sin Server header (seguridad)
- ForwardedHeaders para proxies inversos
- HSTS habilitado para producción
- Rate limiting implementado
- CORS configurable

ENDPOINTS DE LA API:
- GET /api/gta5 - Información del juego GTA V
- GET /api/gta6 - Información del juego GTA VI
- GET /api/locations/properties - Propiedades y negocios
- GET /api/locations/collectibles - Coleccionables
- GET /api/user/profile - Perfil de usuario
- POST /api/user/profile - Actualizar perfil
- POST /api/user/sync - Sincronización con Social Club

3.3 CONFIGURACIÓN DEL FRONTEND
------------------------------
Archivo: gtaapp.client/angular.json

CONFIGURACIÓN DE BUILD:
- Build target: application (Angular 20)
- Output path: dist/gtaapp.client/
- Budgets: 1MB warning, 2MB error para inicial
- Scripts externos: Leaflet CSS

RUTAS DE LA APLICACIÓN:
- /home - Página principal
- /gta5 - Mapa de GTA V
- /gta6 - Mapa de GTA VI (cuenta atrás)
- ** - Redirección a /home

3.4 EJECUCIÓN Y DESARROLLO
--------------------------
MODO DESARROLLO:
1. Backend: cd GTAAPP.Server && dotnet run
2. Frontend: cd gtaapp.client && npm start
3. El backend se conecta automáticamente al frontend (SPA Proxy)

MODO PRODUCCIÓN:
1. Build frontend: cd gtaapp.client && npm run build
2. Ejecutar backend: cd GTAAPP.Server && dotnet run
3. El backend sirve los archivos estáticos del frontend

4. ESTRUCTURA DE DATOS
======================

4.1 ALMACENAMIENTO DE DATOS
---------------------------
- Formato: JSON
- Ubicación: wwwroot/data/
- Archivos principales:
  * properties.json - Propiedades y negocios
  * collectibles.json - Coleccionables
  * user_profile.json - Perfil de usuario

4.2 MODELOS DE DATOS PRINCIPALES
--------------------------------
UserProfile:
- rockstarId: Identificador de Rockstar Games
- nickname: Alias del jugador
- avatarUrl: URL de imagen de avatar
- platform: pc | ps5 | xboxsx
- characterSlot: 0 | 1 (personaje)
- rank: Nivel del jugador (1-8000)
- cash: Dinero en efectivo
- bank: Dinero en banco
- ownedPropertyIds: IDs de propiedades poseídas
- collectedItemIds: IDs de coleccionables recogidos
- highlightOwnedProperties: Booleano para resaltar propiedades
- hideCollectedItems: Booleano para ocultar coleccionables

PropertyLocation:
- id: Identificador único
- name: Nombre de la propiedad
- category: Categoría (mansion, bunker, etc.)
- categoryLabel: Etiqueta visible
- gameMode: story | online | both
- owner: Propietario (opcional)
- price: Precio en dólares
- priceFormatted: Precio formateado
- imageUrl: URL de imagen
- zone: Zona del mapa
- description: Descripción detallada
- features: Lista de características
- income: Ingreso generado
- position: Coordenadas X, Y, Z
- badge: Información visual del marcador

CollectibleItem:
- id: Identificador único
- name: Nombre del coleccionable
- category: Categoría (playing_card, action_figure, etc.)
- categoryLabel: Etiqueta visible
- number: Número en la colección
- total: Total de la colección
- zone: Zona del mapa
- description: Descripción
- hint: Pista para encontrarlo
- reward: Recompensa
- position: Coordenadas X, Y, Z
- badge: Información visual del marcador

5. FLUJOS DE LA APLICACIÓN
===========================

5.1 FLUJO DE INICIALIZACIÓN
---------------------------
1. Usuario accede a la aplicación
2. Angular carga main.ts
3. Se bootstrap AppModule
4. Router redirige a /home
5. HomeComponent se carga
6. Usuario selecciona GTA V o GTA VI

5.2 FLUJO DE CARGA DEL MAPA GTA V
---------------------------------
1. Usuario navega a /gta5
2. GtaMapComponent se inicializa
3. Se inicializa Leaflet map
4. Se carga tile layer según tipo de mapa
5. LocationService carga propiedades desde API
6. LocationService carga coleccionables desde API
7. Se renderizan marcadores en el mapa
8. UserProfileService carga perfil del usuario
9. Se aplican filtros según perfil (propiedades poseídas, etc.)

5.3 FLUJO DE SINCRONIZACIÓN CON SOCIAL CLUB
-------------------------------------------
1. Usuario abre panel de perfil
2. Selecciona pestaña "Sync"
3. Usuario ejecuta script de Tampermonkey o carga JSON manual
4. Datos se envían a POST /api/user/sync
5. UserProfileService procesa y sanitiza datos
6. Se actualiza user_profile.json
7. Se actualiza la vista del mapa con nuevos datos

5.4 FLUJO DE FILTRADO Y VISUALIZACIÓN
-------------------------------------
1. Usuario abre panel de control
2. Selecciona/deselecciona categorías
3. Se selecciona modo de juego (story/online)
4. GtaMapComponent actualiza filtros
5. Se re-renderizan marcadores visibles
6. Se aplica lógica de propiedades poseídas
7. Se actualiza telemetría de coordenadas

6. COMPONENTES Y SERVICIOS
==========================

6.1 COMPONENTES ANGULAR
-----------------------
AppComponent:
- Componente raíz de la aplicación
- No contiene lógica significativa
- Actúa como contenedor de routing

HomeComponent:
- Página de bienvenida
- Opciones para navegar a GTA V o GTA VI
- Diseño minimalista

GtaMapComponent:
- Componente principal del mapa GTA V
- ~1000+ líneas de código
- Lógica compleja de mapas y marcadores
- Gestión de filtros y capas
- Integración con Leaflet
- Panel de control lateral
- Panel de ajustes
- Sistema de coordenadas
- Gestión de marcadores personalizados

Gta6Component:
- Componente del mapa GTA VI
- Cuenta atrás hasta lanzamiento
- Visualización de filtraciones
- Sistema de zoom y pan en canvas
- Leyenda de categorías
- Panel de control similar a GTA V

6.2 SERVICIOS ANGULAR
---------------------
LocationService:
- Servicio para comunicación con API de ubicaciones
- Métodos: getProperties(), getCollectibles()
- Usa HttpClient de Angular
- Manejo de errores básico

UserProfileService:
- Servicio para gestión del perfil de usuario
- Observable profile$ para reactividad
- Métodos: getProfile(), updateProfile(), syncFromSocialClub()
- Métodos helper: isPropertyOwned(), isItemCollected()
- Persistencia local en sesión

6.3 CONTROLADORES ASP.NET CORE
-------------------------------
GTA5Controller:
- GET /api/gta5
- Retorna manifest del juego GTA V
- Información de configuración del mapa

GTA6Controller:
- GET /api/gta6
- Retorna manifest del juego GTA VI
- Estado "proximamente" sin mapa

LocationsController:
- GET /api/locations/properties
- GET /api/locations/collectibles
- Rate limiting específico (data-policy)
- Validación de query parameters
- Filtros por gameMode y category

UserProfileController:
- GET /api/user/profile
- POST /api/user/profile
- POST /api/user/sync
- Sin autenticación (vulnerabilidad crítica)

6.4 SERVICIOS ASP.NET CORE
---------------------------
PropertyImporter:
- Carga y cachea properties.json
- Filtrado por gameMode y category
- Thread-safe con locks
- Reload automático si el archivo cambia

CollectibleImporter:
- Carga y cachea collectibles.json
- Filtrado por category
- Thread-safe con locks

UserProfileService:
- Gestión de user_profile.json
- Sanitización de datos anti-XSS
- Validación de rangos y URLs
- Sincronización con Social Club
- Persistencia thread-safe

6.5 MIDDLEWARE
---------------
SecurityHeadersMiddleware:
- Inyecta cabeceras de seguridad HTTP
- CSP configurado para recursos externos
- X-Frame-Options, X-Content-Type-Options
- Referrer-Policy, Permissions-Policy
- Eliminación de headers informativos

7. SEGURIDAD
============

7.1 MEDIDAS DE SEGURIDAD IMPLEMENTADAS
-------------------------------------
✅ Headers de seguridad HTTP (CSP, X-Frame-Options, etc.)
✅ Rate limiting (120 req/min global, 60 req/min datos)
✅ HSTS configurado correctamente
✅ Sanitización de entrada (HTML encoding, validación de URLs)
✅ Eliminación de headers informativos del servidor
✅ Configuración de CORS basada en entorno
✅ Validación de rangos y whitelist de plataformas

7.2 VULNERABILIDADES IDENTIFICADAS
-----------------------------------
❌ CRÍTICO: Ausencia total de autenticación y autorización
❌ CRÍTICO: Datos sensibles almacenados sin encriptación
⚠️ ALTA: Configuración CORS muy permisiva en desarrollo
⚠️ ALTA: CSP con 'unsafe-inline' y 'unsafe-eval'
⚠️ ALTA: Validación de entrada incompleta
⚠️ MEDIA: Almacenamiento en archivos JSON sin ACI granular
⚠️ MEDIA: Logging potencial de información sensible
⚠️ MEDIA: Falta de verificación de integridad de datos
⚠️ BAJA: Dependencias de frontend requieren auditoría regular
⚠️ BAJA: Falta de monitoreo y alertas de seguridad

7.3 RECOMENDACIONES DE SEGURIDAD
----------------------------------
PRIORIDAD CRÍTICA:
1. Implementar autenticación JWT o OAuth
2. Encriptar datos sensibles en reposo (AES-256)
3. Migrar a base de datos para producción

PRIORIDAD ALTA:
4. Eliminar 'unsafe-inline' de CSP si es posible
5. Implementar autorización basada en roles (RBAC)
6. Restringir orígenes CORS en producción

PRIORIDAD MEDIA:
7. Implementar logging de auditoría
8. Añadir verificación de integridad de datos
9. Implementar monitoreo de seguridad
